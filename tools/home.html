A programming language, built from scratch

Reads like plain English. Checked before it runs.

Zeno is one small language for a quick script and for a microcontroller. Keywords are whole words, punctuation is kept only where it helps, and the compiler finds the mistake and says what to write instead.

Two rules shape the syntax

Most languages inherit their punctuation. Zeno asks each mark to justify itself, and keeps the ones a reader already knows.

1. Words over symbols

Every keyword is a word you can read aloud: function, and, or, not, match, case, raise. There is no fn, &&, => or ?.

2. Punctuation has to earn its place

A mark stays only if it tells the reader something the line does not already say.

Kept

{ }
You always see where a block ends, and a stray space cannot change what the code does.
( ) [ ] ,
Calls, lists and items. Everyone already reads these.
: ->
A name is separated from its type at a glance.
#
A comment. One character, hard to miss.
& | ^ ~ << >>
Bit operators, written the way every datasheet writes a register.

Dropped

;
The line break already ends the statement.
: after if
The brace already opens the block.
( ) around conditions
if x > 0 { needs no help.
&& || !
and, or and not read better.
Truthiness
A condition is true or false. An empty list is not quietly "false".

Types are optional

Write function area(w: float, h: float) -> float, or just function area(w, h). Start loose and add types as the program grows. Where they are left out, the checker works them out when it can.

No surprise none

A value can be none only if its type says or none, and you must check before you use it.

Errors are checked

A function says what it raises. try and except read as they do in Python, and cost little enough for a microcontroller.

Enums carry data

Each case can hold its own values, and a match has to cover every case before the program runs.

Numbers do not wrap by accident

Arithmetic overflow is an error. A u8 is one byte, and wrapping is something you ask for with u8.wrap(n).

Units are types

500 ms and 3.3 V are quantities. A function that wants milliseconds will not take a bare number.

A tour, with the compiler's answers

Each sample below was run with zeno run. What you see under it is exactly what Zeno printed, error messages included.

A variable says once whether it can change. let is set once, var changes, and a plain = updates. Assigning to a misspelt name is an error, never a new variable.

Types are written where you want them and left out where you do not. Functions are values: pass them around, return them, or write one in place.

This program forgets one case. Zeno refuses to run it, names the case, and says how to fix it.

A function declares what it raises. An error passes up until a try catches it. Comparisons chain, as they do in maths.

A value that may be missing has to be checked first. The first print skips the check, so nothing runs.

A number can carry its unit. Passing a bare 20 where milliseconds are wanted is caught before the program runs.

u8, u16, u32, i8, i16 and i32 have a size. Arithmetic gives a full int, u8(n) checks that n fits, and u8.wrap(n) cuts on purpose.

Write a class or function once, with T standing for a type. The call never says what T is. Each use is checked, and compiled as if written by hand for that type.

An owned value has one owner and is freed where that owner's block ends. borrow lends it for a call. Use it after giving it away, and the checker points at the line.

The same language, on a microcontroller

Firmware is where Zeno started. The program below is a traffic light written as a state machine. On a computer the board is simulated, and each line of the log is what a logic analyser clipped to that pin would show.

pin 2pin 3pin 4led
pin 2 on
led on

The simulated board, slowed down 25 times. The excerpt leaves out show and after; the whole program is in examples/signal.zeno.

zeno build --firmware

Errors become return values that every caller tests. The C that comes out has no setjmp.

zeno build --no-collector

For a program where every value has an owner. The garbage collector is left out of the build altogether.

A fixed memory pool

No malloc and no free. Lists and objects live in one array whose size you choose when the C is compiled.

A real board is four C functions

A compiled program meets its board through four functions, so real hardware can be put underneath the same source.

That program makes 2.6 MB of values over its run and never holds more than 13 KB, because each one is freed at a line you can point to.

Inside the compiler

Zeno is written in Rust with no dependencies, so every stage is there to read. One front end feeds four engines, and the tests hold them to the same output.

Source.zeno
Lexertext to tokens
Parsertokens to a syntax tree
Checkertypes, none, errors, ownership
Interpreterzeno runWalks the syntax tree. The reference for what a program means.
Bytecode VMzeno run --vmA stack machine, two to three times as fast.
C backendzeno buildPortable C, for any chip with a C compiler.
LLVM backendzeno build --llvmTextual LLVM IR, built with clang. No LLVM library needed.

Memory, three ways

A small mark-and-sweep collector by default. owned values freed where their owner ends. Or no collector at all, on a fixed pool.

Every stage is documented

Each part of the compiler has a walkthrough that ends in things to try, from the lexer to the LLVM backend.

Every decision has a reason

One document records each design choice, why it was made and what was turned down. If you disagree, you can see what you are disagreeing with.

One language, every job

The goal is that anything you would reach for C, C++, Python, JavaScript, Java or Rust to do, you can do in Zeno. That is a long road. This is where it stands.

  • Scripts and automationInterpreter and bytecode VMWorks today
  • Microcontrollers and firmwareCompiles to C with no heap, on a simulated boardWorks today
  • Native programsThrough C or LLVMWorks today
  • Manual memoryunsafe { }, raw pointers, memory-mapped registersNext
  • Standard libraryFiles, text, collections, and modules across filesPlanned
  • ToolingPackage manager, formatter, editor supportPlanned
  • Calling C librariesC interop, in both directionsPlanned
  • Web front endsA WebAssembly backendPlanned
  • Servers and networkingasync and awaitPlanned
  • Data and numericsFast arrays and operator overloadingPlanned

Zeno is young and the syntax can still change. It is a language to learn from and experiment with, and not yet one to ship a product on.

Run it yourself

You need Rust to build Zeno, and a C compiler for zeno build. There is nothing else to install.

zeno run file.zenoCheck a program, then run it.
zeno run --vm file.zenoThe same, on the bytecode VM.
zeno check --strict file.zenoEvery type must be known, as firmware needs.
zeno build file.zenoCompile to C, then to a program.
zeno build --llvm file.zenoCompile through LLVM IR and clang.
zeno bytecode file.zenoShow the VM's instructions, one per line.
