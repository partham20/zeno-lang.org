Code that reads like what it means.

Zeno is a programming language for a quick script and for a microcontroller. Keywords are whole words, punctuation stays only where it helps, and every program is checked before it runs.

Two rules shape every line.

Most languages inherit their punctuation. Zeno asks each mark what it tells the reader, keeps the ones everyone already reads, and turns the rest into words.

Kept, because it helps

{ }
You always see where a block ends, and a stray space cannot change what the code does.
( ) [ ] ,
Calls, lists and items. Everyone already reads these.
: ->
A name is set apart from its type at a glance.
#
A comment. One character, hard to miss.
& | ^ << >>
Bit operators, written the way every datasheet writes a register.

Dropped, because it repeats

;
The line break already ends the statement.
&& || !
and, or and not say it in words.
( ) around a condition
if x > 0 { needs no help.
fn => ?
Every keyword is a word you can say aloud: function, match, case.
truthiness
A condition is true or false. An empty list is not quietly false.

Read the reason for every choice

A tour, with the compiler's own answers.

Every sample was run with zeno run. What is printed under it is exactly what Zeno said, error messages included.

Say once if it changes

let is set once, var can change, and a plain = updates. A type goes after the name, and only where you want one.

Functions are values

Types are written where you want them. Arguments can be named, parameters can have defaults, and a function with no name is written in place.

Every case, or nothing runs

Each case of an enum can carry values, and match takes them apart. This program forgets one case, so Zeno names it and stops.

Errors you can see coming

A function says what it raises, and the checker makes sure someone handles it. Comparisons chain, as they do in maths.

No surprise none

A value can be missing only if its type says or none, and it has to be checked before use. The first print skips the check.

Units are part of the type

500 ms and 3.3 V are quantities. A function that wants milliseconds will not take a bare number.

A u8 is one byte

Sized numbers and the bit operators, for registers and packets. u8(n) checks that n fits, and u8.wrap(n) cuts on purpose.

Written once, for any type

T stands for a type, and a call never has to say which. Each use is compiled as if written by hand for that type.

One owner, freed on time

An owned value is freed where its owner's block ends. A parameter only looks, unless it says take. Use a value after giving it away, and the checker points at the line.

The whole language, a step at a time

Mistakes stop at the checker.

Nothing runs until the whole program makes sense. Each message points at the line and says what to write instead.

  • A misspelt name

    Plain = only updates, so a typo cannot quietly make a new variable.

    cuont = count + 1count = count + 1

  • A forgotten case

    A match must handle every case of the enum.

    no case for Dotcase Dot { return 0.0 }

  • A value that may be missing

    Anything that can be none is checked before it is used.

    user.upper()if user is not none { }

  • A number with no unit

    Milliseconds stay milliseconds, all the way down.

    blink_for(20)blink_for(20 ms)

  • A condition that is not a yes or no

    There is no truthiness to remember.

    if items {if len(items) > 0 {

  • A value used after it was given away

    Ownership is checked, with no garbage collector needed.

    print(frame.channel)send(frame) last

One job, four ways.

A sensor gives five readings. Throw away the ones out of range and average the rest. Zeno does not make you pick a style.

let readings = [21.5, 22.0, -99.0, 21.0, 150.0]

All four print 21.5

The same language, on a microcontroller.

Firmware is where Zeno started. This traffic light is a state machine on three pins. On a computer the board is simulated, and each line of the log is what a logic analyser on that pin would show.

Simulated board, 25 times slower
pin 2pin 3pin 4led
pin 2 on
led on

The excerpt leaves out show and after. The whole program is examples/signal.zeno.

  • Errors as values

    --firmware turns every error into a return value the caller tests. No setjmp.

  • No garbage collector

    --no-collector leaves it out. Every value has one owner and is freed on a line you can point to.

  • One fixed pool

    No malloc. Lists and objects live in one array whose size you choose.

  • Four C functions to a board

    A compiled program meets real hardware through four functions you write once.

That program makes 2.6 MB of values over its run and never holds more than 13 KB at once.

How the firmware build works

One front end, four engines.

The compiler is plain Rust with no dependencies, so every stage is there to read. The tests run each program on all four engines, and they must print the same.

SourceA .zeno file.
LexerText into tokens.
ParserTokens into a syntax tree.
CheckerTypes, none, errors and owners.
InterpreterWalks the tree. The reference for what a program means.zeno run
Bytecode VMA stack machine, two to three times as fast.zeno run --vm
C backendPortable C, for any chip with a C compiler.zeno build
LLVM backendLLVM IR, built with clang.zeno build --llvm

Memory, three ways

A small collector by default, owned values freed where their owner ends, or no collector at all on a fixed pool.

Every stage is written up

Each part of the compiler has a walkthrough that ends with things to try.

Every decision has a reason

One document records each choice, why it was made, and what was turned down.

Walk through the compiler

Write it once, read it in fifteen languages.

New in 0.5 zeno build --target writes your program in another language: a file you can read, keep, and run with that language's own tools. It follows fixed rules, so the same program gives the same file every time.

  • JavaScript--target jsnode hello.js
  • TypeScript--target tsnode hello.ts
  • A web page--target htmla browser
  • Python--target pypython3 hello.py
  • PHP--target phpphp hello.php
  • Lua--target lualua hello.lua
  • Ruby--target rubyruby hello.rb
  • Dart--target dartdart run hello.dart
  • Kotlin--target kotlinkotlinc hello.kt -include-runtime -d hello.jar
  • Go--target gogo run hello.go
  • Java--target javajava hello.java
  • C#--target csdotnet run hello.cs
  • C++--target cppg++ -std=c++17 -O2 hello.cpp -o hello
  • Rust--target rustrustc -O --edition 2021 hello.rs -o hello
  • WebAssembly--target wasmwasmtime hello.wasm

It does what zeno run does

The same text, the same errors on the same line, and numbers that overflow where Zeno's do, even in JavaScript and Python.

Held to it by a tool

Every example and every sample in the book is built for every target, run, and compared with zeno run.

One file, nothing else

Zeno's rules for that language go at the top of the file, so it needs no library and no install of Zeno.
