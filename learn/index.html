The Zeno guide

Everything in the language, a step at a time. Every sample on this page was run with zeno run, and what is under it is exactly what Zeno printed, error messages included. If you know Python or C, you can read it in twenty minutes.

Step 1 of 25

Install

Zeno 0.5 is out, open source under the MIT licence. Install it with one line on macOS and Linux, or a setup program on Windows. Both put zeno on your PATH, and offer a C compiler and git if the machine has none: zeno build needs the first, zeno fetch the second, and nothing else needs either.

macOS and Linux

Windows

Download zeno-0.5.1-windows-setup.exe, run it and press Next. One file covers x86-64, 32-bit x86 and ARM64. It is not signed, so Windows warns the first time: choose “More info”, then “Run anyway”.

With a package manager

There are packages for apt, pacman, snap and flatpak, installed from the file on the release page, and a Homebrew tap:

The .deb is also there for arm64, armhf and i386, the snap for arm64 and armhf, and the flatpak for aarch64. Plain archives for ten kinds of machine, with SHA256SUMS.txt, are on the release page. How the installers work and what each package is are in the docs.

From source

You need Rust, and nothing else. Or skip installing for now, and try it in the playground.

Step 2 of 25

Your first program

A program is a file of statements, run from the top. There is no main, nothing to import for printing, and no semicolons: a line break ends a statement.

Step 3 of 25

Variables

A variable says once whether it can change. let is set once. var can change, and a plain = updates it. const is fixed when the program is built. A type goes after the name, and only where you want one.

Step 4 of 25

A misspelt name is an error

Because = only updates, assigning to a name that was never declared cannot quietly make a new variable. The checker stops before anything runs, and says what to write.

Step 5 of 25

Numbers

/ always gives a float and // divides and rounds down, so you can see which one you meant. Comparisons chain as they do in maths. An int and a float can be mixed in arithmetic; nothing else converts by itself.

Step 6 of 25

Overflow is an error

Whole-number arithmetic is checked. A sum that does not fit is an error you can catch, never a silent wrap to a negative number.

Step 7 of 25

Choices and loops

if, else if, for and while need no brackets around the condition and no colon after it. The brace opens the block, and the block always has braces, so a stray space can never change what the code does.

Step 8 of 25

Conditions are true or false

There is no truthiness. An empty list, zero and empty text are not quietly false: write what you mean, such as len(items) > 0.

Step 9 of 25

Functions

A function is declared with the word function. Types on parameters and the result are optional. Arguments can be named, parameters can have defaults, and a function with no name is written in place with function(n) { }.

Step 10 of 25

Functions that remember

A function written inside another keeps the variables it can see, and can change them.

Step 11 of 25

Lists and text

Lists are written with [ ], and have append, map, filter and reduce. Comprehensions read like the sentence they stand for. Formatted text needs the f prefix, so a brace in ordinary text is just a brace.

Step 12 of 25

Dictionaries

A dict keeps one value under each key, written with the same square brackets as a list: ["temp": 85], and [:] for an empty one. Asking for a key that was never stored is an error, not a quiet zero; get gives none or a default instead.

Step 13 of 25

Classes

A class lists its fields at the top and gets a constructor for free, which takes the fields in order or by name. Methods name self explicitly.

Step 14 of 25

Enums and match

Each case of an enum can carry its own values, and match takes them apart. A match must handle every case. This one forgets Dot, so nothing runs.

Step 15 of 25

Values that may be missing

A value can be none only if its type says or none. Before you use it, you check it with is not none, and inside that check it is the plain type.

Step 16 of 25

Errors

try, except and raise read as they do in Python. A function that can fail says so with raises, and the checker makes sure the error is handled or passed on. Any class can be raised, so an error can carry data.

Step 17 of 25

Files and input

import files reads and writes files, input() reads a line from the keyboard, and import program gives the words a program was started with. A file that is not there is a FileError you can catch.

Step 18 of 25

Units

A number can carry a unit: 500 ms, 3.3 V. The unit is part of the type, so a function that wants milliseconds will not take a bare number.

Step 19 of 25

Numbers with a size

u8, u16, u32, i8, i16 and i32 have a size, and &, |, ^, ~, << and >> work on their bits. Arithmetic gives a full int, u8(n) checks that n fits, and u8.wrap(n) keeps the low eight bits on purpose. A u8 field is one byte in a compiled object.

Step 20 of 25

Generics

class Stack[T] and function largest[T] are written once, with T standing for a type. A call never says what T is: the checker works it out, and the compilers make one copy for each type used, so a Stack[u8] is as small as one written for bytes by hand.

Step 21 of 25

Owned values

Most values are shared, and a garbage collector frees them. A value marked owned has one owner instead, and is freed the moment its owner's block ends. A parameter only looks at what it is given, unless it says take. Giving the value away empties the old name, and the checker points at any later use.

Step 22 of 25

Programs in several files

A file is a module. import sensors brings in sensors.zeno from the same folder, and its names are written sensors.check; from sensors import Reading brings in one name to use as it is. A dot is a folder, so import drivers.uart is drivers/uart.zeno. There is nothing to declare and nothing to export: what a file declares at the top is what others can import. See the weather station in examples/station, four files with its output.

Step 23 of 25

Pins and time

from board import led, pin and from time import sleep, now give a program pins and a clock. On a computer the board is simulated and prints each pin as it changes. A compiled program meets a real board through four C functions.

Step 24 of 25

Building for speed

zeno run runs a program straight away and checks everything. zeno build compiles it to C and keeps the checks: an index out of range, a division by zero and an overflow still stop the program with Zeno's message. When the tests pass, two choices make it faster. --owned gives every list and object one owner and frees it on the line its owner ends, with no collector at all. --fast leaves out the checks that a correct program never fails, as C does, and runs about as fast as C and Rust.

A wrong index in a --fast build is a wrong answer or a crash, exactly as in C, so build the ordinary way while a program is being written. Choosing how memory is freed and the benchmarks say more.

Step 25 of 25

Other languages

zeno build --target writes your program in another language: JavaScript, TypeScript, Python, PHP, Go, Java, C#, C++ or Rust, a web page, or a WebAssembly file. The file needs nothing else, and it prints what zeno run prints, down to the same error on the same line.

The same program gives the same file every time. A program that uses the board, a web page or memory by hand stays with Zeno's own builds. How the targets work.

Reference

The commands

One program, zeno, does everything. Every command checks the program first, and nothing runs if the check fails.

zeno run file.zeno
Check it, then run it with the interpreter.
zeno run --vm file.zeno
The same, compiled to bytecode and run by the VM.
zeno check file.zeno
Only look for mistakes.
zeno check --strict file.zeno
Every type must be known, as firmware needs.
zeno build file.zeno
Compile to C, then to a program.
zeno build --llvm file.zeno
Compile to LLVM IR, then to a program with clang.
zeno build --firmware
Errors as return values, no setjmp.
zeno build --no-collector
No garbage collector and no heap: one fixed pool.
zeno build --memory
The program reports its memory use as it ends.
zeno test
Run the tests in a file or a folder.
zeno format file.zeno
Lay the file out the one standard way.
zeno new name
Make a folder with a new program; --package makes a package.
zeno fetch
Get the packages the program needs.
zeno join file.zeno
Show the one program a file and its imports join into.
zeno lsp
The language server, for editors.
zeno bytecode, parse, tokens
Look inside: the instructions, the syntax tree, the tokens.
