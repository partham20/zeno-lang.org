    Use a package

    A package is named by its name and one exact version. There are no ranges: the version you write is the version you get.

    1. Add the line to the zeno.package of your program. 
      package thermostat

needs filters at "v1.0.0"
    2. Fetch it, in the program's folder. The packages it needs come too, and zeno.lock records the exact commit of each. 
      zeno fetch
    3. Import it. 
      import filters

print(filters.mean([18.2, 18.9, 19.6]))

    Publish a package

    A package stays in your own git repository. The registry records where it is, and which commit each version is.

    1. Say what it is for, in its zeno.package. 
      package filters
about "Filters for noisy readings"
    2. Tag a commit with its version, and push it. 
      git tag v1.0.0
git push origin main v1.0.0
    3. Check it, and get the address of the form that asks the registry to take it. 
      zeno publish
    4. Open that address, signed in to GitHub, and press the button. The registry checks the package and answers there.

    What the registry promises

    • A published version never changes. The registry keeps the commit a tag named on the day it was published, and that commit is what everybody gets.
    • A name has one owner. The first to publish a name publishes its later versions, from the same repository.
    • Nothing is hidden. The registry is a git repository with one small text file for each package. There is no server and no account to make.
    • Only zeno fetch uses the network. Running and building a program read files and nothing else.

    How it works, line by line: the registry walkthrough. A package from a git repository that is in no registry, or from a folder beside the program, works as before.
